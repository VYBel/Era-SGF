# Полный архив: библиотека 1.2.0

Проверено 117 245 подготовленных SGF (116 378 профессиональных/исторических,
402 с ИИ, 465 на других размерах доски). Личные файлы, их имена и база измерений
не включены в Git. Исходные SGF в замерах не изменялись; использовались отдельные
каталоги состояния под `local/library-benchmark/`.

## Реализация

- Индекс путей заменяет линейный поиск при обновлении и действиях над файлами.
- Обновление обходит директории, но читает и разбирает только новые/изменённые SGF.
  Проверяются размер, mtime/ctime и наносекунды. Неизменённые записи переиспользуются.
- «Перепроверить все файлы» принудительно читает содержимое. Это необходимо, если
  внешнее редактирование сохранило размер и все timestamps, в том числе на FAT с
  грубой точностью времени. Действия над конкретной партией дополнительно сверяют
  отпечаток содержимого, как и раньше.
- Первое обращение к библиотеке/случайной партии в сессии обновляет список.
  Последующие обращения используют каталог; новые внешние файлы можно обнаружить
  кнопкой «Обновить список партий». Фонового сканирования нет.
- Результат поиска/сортировки переиспользуется при листании страниц; изменения
  данных или фильтра сбрасывают кэш.
- Полный каталог пишется потоком в атомарно заменяемый файл. Небольшие действия
  пишут атомарный пакет изменений с контрольной суммой и поколением каталога.
  При 512 операциях либо достижении порядка 1 МиБ изменений выполняется уплотнение.
  Старый пакет после замены полного каталога игнорируется по поколению.
- Повреждённый пакет не применяется частично: остаётся состояние последнего
  полного каталога, ошибка пишется в diagnostics.log. Изменения из повреждённого
  пакета могут быть утрачены; оригинальные SGF он не меняет.
- Жёсткий предел 20 000 файлов удалён. Защитный предел сериализованного каталога —
  256 МиБ; это не обещание неограниченного размера. Проверенный объём — 117 245 файлов.
  Каталог метаданных остаётся в памяти; SQLite и новые зависимости не добавлены.

## Измерения на компьютере

Linux x86-64, AMD Ryzen 7 9700X, около 30,5 ГиБ RAM; C++14/GCC, `-O2`.
Один последовательный сценарий на коллекции, уже читавшейся системой: файловый
кэш ОС не сбрасывался. Значения округлены. Это измерения ядра библиотеки, без
InkView, framebuffer и открытой партии; **не скорость или память PocketBook**.

Для сравнения взята реализация 1.1.1 (`0d2909e`), в отдельной копии подняты только
пределы количества файлов и размера каталога: иначе она прекращает работу на
20 001-м файле. Её повторная загрузка отдельно проверена: все 117 245 записей
сохранились. Поэтому столбец «до» — сравнение алгоритмов, а не запуск неизменённого
релиза на полном архиве.

| Операция | До, с | После, с |
|---|---:|---:|
| Первая индексация | 7,211 | 4,186 |
| Повторное открытие каталога | 0,159 | 0,148 |
| Обновление без изменений | 12,658 | 0,386 |
| Первый запрос всех партий | 0,0256 | 0,0210 |
| Первый поиск по тексту | 0,0543 | 0,0480 |
| 100 повторений того же поиска | 4,244 | 0,0000675 |
| 100 случайных выборок | 0,0148 | 0,0133 |
| Сохранение одной отметки просмотра | 2,867 | 0,00153 |
| Пик RSS всего сценария, МиБ | 254,8 | 114,6 |

Первый проход разобрал 117 245 файлов; неизменённое обновление разобрало **0**,
переиспользовав **117 245** записей. RSS — `getrusage(RUSAGE_SELF).ru_maxrss`,
накопленный максимум процесса, а не текущее потребление каждой отдельной операции.
При обновлении с изменениями временно создаётся новый набор метаданных, поэтому
пик такого сценария может быть выше. Каталог v2 на этом наборе занимает около
46 МиБ. Показатели не являются гарантией для любого SGF или накопителя.

Повторение замера:

```bash
make build/era-sgf-library-benchmark
build/era-sgf-library-benchmark /absolute/path/to/storage-root /absolute/path/to/separate-benchmark-state
```

Корень должен содержать `sgf/`. Для первой индексации укажи новый отдельный каталог
состояния. Инструмент меняет и возвращает отметку просмотра в этой отдельной базе,
не удаляет и не переписывает партии. Вывод: операция, секунды, пик RSS в КиБ.
Исходные результаты этой проверки: `local/library-benchmark/before.tsv`,
`reported.tsv`, логи сборок и тестов рядом.

## Совместимость и проверка

База v1 читается со статусами просмотра; первый проход заполняет новые timestamps.
Исторические годы пересчитываются из DT/пути без поиска случайных чисел в хеше имени.
Состояние позиции открытой партии сохраняется прежним механизмом.

**Перед обновлением книги нужно сохранить весь `system/config/era-sgf`, а не только
бинарник.** Старая версия 1.1.1 не читает каталог v2. Для отката восстанавливаются
прежний бинарник и прежнее состояние; изменения просмотра после обновления при
таком откате не сохранятся. Сборка установлена на Era 700; файлы приложения и подготовленный каталог проверены после записи. Пользовательское состояние сохранено.

142 проверки: 37 core, 53 UI, 20 library, 7 files, 3 package, 22 installer.
Тот же набор проходит ASan/UBSan. Отдельно проверены миграция v1, отказ записи,
устаревший/повреждённый пакет изменений, метаданные больше 1 МиБ, поиск по 25 001
записи, symlink-пути и сохранение отметок после перемещения. ARM B288 собран.
Фактические замеры скорости и памяти на процессоре Era остаются отдельным следующим шагом. Проверка установленного каталога выполнялась с компьютера через USB; работу интерфейса на устройстве она не подтверждает.
