## Быстрый случайный выбор: 1.2.3

`library.random` — производный двоичный индекс: заголовок 64 байта, таблица по
32 байта на партию (хеш пути, хеш содержимого, смещение/длина пути, флаги
просмотра и корректности) и строки относительных путей. В память читается таблица,
пути — только для выбранных файлов и записей из небольшого журнала изменений.
Метаданные игроков, турниров и комментариев не загружаются. Индекс связан с
поколением `library.db`; таблица и выбранные пути проверяются по контрольным суммам.

Индекс строится при сохранении снимка или явном обновлении библиотеки. Отметки
просмотра сохраняются в прежнем журнале/очереди отдельных записей и применяются
поверх индекса при выборе, поэтому переписывать весь индекс после каждого хода
не нужно. Замена содержимого сбрасывает отметку по прежним правилам. Отсутствующий
случайный файл пропускается. Начиная с 1.2.4 перебор ограничен 32 проверками
и бюджетом 250 мс между проверками: при достижении любого порога следующие
попытки прекращаются. Отдельный системный вызов чтения этим бюджетом не прерывается.
При неудаче предлагается явно обновить список, фонового продолжения нет.
Новые файлы попадают через обновление или непосредственное открытие SGF.

Отсутствие, повреждение или несовпадение поколения индекса приводит к предложению
обновить библиотеку, без автоматического чтения полного каталога. При обновлении
книги с 1.2.2 индекс можно подготовить на компьютере по копии существующего
каталога; пользовательские файлы состояния при этом не изменяются.
Полноэкранная библиотека с фильтрами всё ещё загружает полные метаданные по запросу.

Отложенные изменения читаются по одному разу, а в overlay остаются только путь,
хеш содержимого и флаги. При длительном использовании только случайного выбора
число pending-файлов растёт; стоимость их чтения линейная. Явный вход в библиотеку
объединяет очередь с каталогом. Отдельного фонового таймера/пересканирования нет.
На хосте 117 309 записей и 1000 pending проверены под лимитом адресного пространства
32 МиБ: 51–52 мс под strace, пик RSS 11,5 МиБ. Скорость мелких чтений на самой
книге требует отдельной проверки; кэширование ОС влияет на замеры.

# Полный архив: библиотека 1.2.0

## Каталог по запросу: 1.2.2

Пользователь подтвердил запуск 1.2.1 с полным архивом. Журнал на Era 700 показал
39 352 и 39 798 мс на загрузку 117 309 записей; пик RSS — 79 896 КиБ. Это уже
измерения приложения на книге, хотя счётчик времени включает таймеры/отрисовку,
а не только CPU декодирования. Повторное чтение базы при каждом запуске осталось
неудобным, поэтому в 1.2.2 оно исключено из обычного просмотра.

Отдельный SGF читается независимо от базы, а его метаданные и явные отметки
пишутся в небольшую атомарную запись `library.pending/`. При первом явном входе
в библиотеку очередь объединяется с базой: открытие существующей партии не
сбрасывает её отметку; новый файл добавляется; замена содержимого сбрасывает
прежнюю отметку. Небольшое число изменений использует существующий журнал.
Очередь удаляется и её удаление синхронизируется только после фиксации данных.
Повторное применение после прерывания идемпотентно. Ошибка загрузки оставляет
просмотр отдельного файла доступным. Перед откатом на 1.2.1 нужно дождаться
объединения очереди в библиотеке новой версии; старый формат снимка v2 не менялся.

Каталог читается по запросу для библиотеки, случайного выбора и перемещения/
удаления. При простом просмотре и пометке полного чтения нет. Обход директорий
и перечитывание SGF выполняются только через команды обновления в инструментах
библиотеки, в том числе при первом использовании пустой библиотеки.

На копии полного каталога `strace` подтвердил ноль открытий `library.db` и ноль
обходов папок при прямом открытии SGF и обычном повторном запуске. Оба сценария
прошли с лимитом адресного пространства 32 МиБ; пик RSS хостового адаптера около
7 МиБ. Явный вход в библиотеку загрузил весь каталог и добавил открытый файл.
Это проверки на компьютере; скорость новой версии и физическая лампочка Era
требуют отдельной проверки после установки.

Статический просмотр не оставляет активных таймеров и разрешает автоматический
сон/выключение. Завершение callbacks клавиатуры и подтверждений явно вызывает
`ForcingSleep`, как и завершение обычных событий. Только активное автолистание
запрещает автоматическую блокировку/выключение. Текст документации локального
SDK определяет `ForcingSleep` как запрос сна после завершения текущей работы;
это не прямое управление индикатором и не измерение потребления устройства.

## Уточнение после проверки на книге: 1.2.1

При запуске 1.2.0 пользователь наблюдал зависание. Загрузка всего каталога шла
в конструкторе до `InkViewMain`, то есть до первого кадра и обработки кнопок.
Кроме того, первый вход в библиотеку автоматически обходил архив. На проверенном
наборе метки ctime/наносекунд после переноса между Linux-компьютером и прошивкой
отличались почти у всех файлов при неизменном mtime: автоматическая проверка
могла перечитать архив целиком. Это отдельная тяжёлая операция, не часть конструктора.

В 1.2.1 сначала рисуется заставка; каталог читается короткими порциями по таймеру.
Порция ограничена 256 строками и проверкой времени после каждой строки (8 мс).
Это мягкий бюджет обработки, не жёсткая гарантия задержки: одно чтение, большая
строка, расширение контейнера или применение небольшого журнала могут занять дольше.
Выход во время загрузки не пишет каталог и позицию; скрытие приостанавливает
таймер, возвращение продолжает чтение. Процент обновляется не чаще раза в секунду
частичным обновлением экрана; после загрузки активных таймеров нет.

Готовый каталог больше не обновляется автоматически при первом входе в библиотеку
или выборе случайной партии. Внешние изменения обнаруживаются через
«Обновить список партий». Если полного каталога ещё нет, первое явное открытие
библиотеки по-прежнему строит его синхронно; ручное обновление большого архива
также может быть долгим. Сравнение timestamps при таком обновлении остаётся строгим.

Проверка адаптера на копии каталога из 117 309 записей: сохранены четыре отметки,
байты базы не изменились. `strace` подтвердил **0 обходов директорий и 0 открытий
SGF** при запуске без выбранного файла и открытии библиотеки. На компьютере под
strace сценарий занял около 0,3 с, пик RSS около 94 МиБ. Это не замер ARM/E Ink.
Метаданные по-прежнему целиком находятся в памяти; этот патч не вводит дисковую БД.

`system/config/era-sgf/diagnostics.log` теперь содержит строку `startup` с версией,
`catalogue_ms` (время от создания приложения, включая паузы), `rows`,
`peak_rss_kib` и `max_step_ms`. По ней можно проверить следующий запуск на книге.
Точный источник задержки на процессоре Era и результат исправления требуют
повторной проверки пользователем. Далее сохранены исторические замеры 1.2.0.

Проверено 117 245 подготовленных SGF (116 378 профессиональных/исторических,

## Реализация

- Индекс путей заменяет линейный поиск при обновлении и действиях над файлами.
- Обновление обходит директории, но читает и разбирает только новые/изменённые SGF.
  Проверяются размер, mtime/ctime и наносекунды. Неизменённые записи переиспользуются.
- «Перепроверить все файлы» принудительно читает содержимое. Это необходимо, если
  внешнее редактирование сохранило размер и все timestamps, в том числе на FAT с
  грубой точностью времени. Действия над конкретной партией дополнительно сверяют
  отпечаток содержимого, как и раньше.
- В 1.2.0 первое обращение к библиотеке/случайной партии в сессии обновляло список.
  Последующие обращения используют каталог; новые внешние файлы можно обнаружить
  кнопкой «Обновить список партий». Фонового сканирования нет.
- Результат поиска/сортировки переиспользуется при листании страниц; изменения
  данных или фильтра сбрасывают кэш.
- Полный каталог пишется потоком в атомарно заменяемый файл. Небольшие действия
  пишут атомарный пакет изменений с контрольной суммой и поколением каталога.
  При 512 операциях либо достижении порядка 1 МиБ изменений выполняется уплотнение.
  Старый пакет после замены полного каталога игнорируется по поколению.
- Повреждённый пакет не применяется частично: остаётся состояние последнего
  полного каталога, ошибка пишется в diagnostics.log. Изменения из повреждённого
  пакета могут быть утрачены; оригинальные SGF он не меняет.
- Жёсткий предел 20 000 файлов удалён. Защитный предел сериализованного каталога —
  256 МиБ; это не обещание неограниченного размера. Проверенный объём — 117 245 файлов.
  Каталог метаданных остаётся в памяти; SQLite и новые зависимости не добавлены.

## Измерения на компьютере

Linux x86-64, AMD Ryzen 7 9700X, около 30,5 ГиБ RAM; C++14/GCC, `-O2`.
Один последовательный сценарий на коллекции, уже читавшейся системой: файловый
кэш ОС не сбрасывался. Значения округлены. Это измерения ядра библиотеки, без
InkView, framebuffer и открытой партии; **не скорость или память PocketBook**.

Для сравнения взята реализация 1.1.1 (`0d2909e`), в отдельной копии подняты только
пределы количества файлов и размера каталога: иначе она прекращает работу на
20 001-м файле. Её повторная загрузка отдельно проверена: все 117 245 записей
сохранились. Поэтому столбец «до» — сравнение алгоритмов, а не запуск неизменённого
релиза на полном архиве.

| Операция | До, с | После, с |
|---|---:|---:|
| Первая индексация | 7,211 | 4,186 |
| Повторное открытие каталога | 0,159 | 0,148 |
| Обновление без изменений | 12,658 | 0,386 |
| Первый запрос всех партий | 0,0256 | 0,0210 |
| Первый поиск по тексту | 0,0543 | 0,0480 |

| Пик RSS всего сценария, МиБ | 254,8 | 114,6 |

Первый проход разобрал 117 245 файлов; неизменённое обновление разобрало **0**,
переиспользовав **117 245** записей. RSS — `getrusage(RUSAGE_SELF).ru_maxrss`,
накопленный максимум процесса, а не текущее потребление каждой отдельной операции.
При обновлении с изменениями временно создаётся новый набор метаданных, поэтому
пик такого сценария может быть выше. Каталог v2 на этом наборе занимает около
46 МиБ. Показатели не являются гарантией для любого SGF или накопителя.

Повторение замера:

```bash
make build/era-sgf-library-benchmark
build/era-sgf-library-benchmark /absolute/path/to/storage-root /absolute/path/to/separate-benchmark-state
```

Корень должен содержать `sgf/`. Для первой индексации укажи новый отдельный каталог
состояния. Инструмент меняет и возвращает отметку просмотра в этой отдельной базе,
не удаляет и не переписывает партии. Вывод: операция, секунды, пик RSS в КиБ.
Исходные результаты этой проверки: `local/library-benchmark/before.tsv`,
`reported.tsv`, логи сборок и тестов рядом.

## Совместимость и проверка

База v1 читается со статусами просмотра; первый проход заполняет новые timestamps.
Исторические годы пересчитываются из DT/пути без поиска случайных чисел в хеше имени.
Состояние позиции открытой партии сохраняется прежним механизмом.

**Перед обновлением книги нужно сохранить весь `system/config/era-sgf`, а не только
бинарник.** Старая версия 1.1.1 не читает каталог v2. Для отката восстанавливаются
прежний бинарник и прежнее состояние; изменения просмотра после обновления при
таком откате не сохранятся. Сборка установлена на Era 700; файлы приложения и подготовленный каталог проверены после записи. Пользовательское состояние сохранено.

142 проверки: 37 core, 53 UI, 20 library, 7 files, 3 package, 22 installer.
Тот же набор проходит ASan/UBSan. Отдельно проверены миграция v1, отказ записи,
устаревший/повреждённый пакет изменений, метаданные больше 1 МиБ, поиск по 25 001
записи, symlink-пути и сохранение отметок после перемещения. ARM B288 собран.
Фактические замеры скорости и памяти на процессоре Era остаются отдельным следующим шагом. Проверка установленного каталога выполнялась с компьютера через USB; работу интерфейса на устройстве она не подтверждает.
