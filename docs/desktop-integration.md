# Значок Era-SGF и раздел «Игры»

`scripts/install-mounted-reader.py` работает на компьютере с Python 3.9+ под
Linux/POSIX. На книгу устанавливаются один `applications/era-sgf.app` и два BMP;
Python и дополнительные библиотеки на ней не нужны. Сам установщик в ZIP не входит.

## Предварительная проверка и установка

Подключи книгу по USB и укажи корень её доступной памяти. Сначала проверь план:

```bash
python3 scripts/install-mounted-reader.py \
  --root /path/to/mounted-reader \
  --archive dist/Era-SGF-1.0.1-b288.zip \
  --backup-dir local/reader-backups
```

Без `--apply` команда только читает файлы. Она выводит JSON с SHA-256 архива,
изменениями (`changes`) и сохранёнными существующими примерами (`preserved`).
Каталог резервных копий пока не создаётся. Путь по умолчанию —
`local/reader-backups` относительно репозитория со скриптом; резервные копии должны
находиться вне памяти книги.

Для применения проверенного архива добавь `--apply`:

```bash
python3 scripts/install-mounted-reader.py \
  --root /path/to/mounted-reader \
  --archive dist/Era-SGF-1.0.1-b288.zip \
  --backup-dir local/reader-backups \
  --apply
```

После завершения безопасно извлеки устройство средствами ОС, отключи USB и
проверь Era-SGF в разделе «Игры» рядом с шахматами. Отображение и обновление
значков самим launcher требуют проверки на конкретной прошивке.

## Как меняется конфигурация

Установщик читает существующий `system/config/desktop/view.json` версии 7
(строка `"7"`, как на проверенной Era, либо число `7`; тип сохраняется) и
добавляет приложение с ID `U_EraSGF`:

```json
{
    "path": "/mnt/ext1/applications/era-sgf.app",
    "title": "Era-SGF",
    "icon": { "path": "applications/icons/era-sgf.bmp" },
    "focused_icon": { "path": "applications/icons/era-sgf-focused.bmp" }
}
```

В `view.groups` используется существующая группа с `title: "@Games"`. В неё
добавляется один `U_EraSGF`; такой же ID убирается из остальных групп. Порядок
остальных приложений, свойства групп, версия, `_comment` и неизвестные поля
сохраняются. Неизвестные поля уже зарегистрированного Era-SGF, в том числе
дополнительные свойства объектов иконок, тоже сохраняются. Если этот ID занят
другим исполняемым файлом, установка останавливается.

При первом изменении JSON получает отступы в четыре пробела; содержимое строк
комментариев сохраняется. Если данные и регистрация уже актуальны, конфигурация
и приложение не переписываются и новая резервная копия не создаётся.
Отсутствие `@Games`, другая версия или неоднозначная структура требуют ручной
проверки формата. Конфигурации отдельных пользовательских профилей автоматически
не перебираются.

Формат основан на комментариях реальной конфигурации версии 7. Общая
[инструкция Taranis](https://github.com/orontee/taranis/blob/main/docs/desktop_integration.md)
подтверждает расположение `view.json` и пару BMP, но её старый пример со строковыми
полями `icon` не используется.

## Сохранение данных и резервные копии

До первой записи установщик полностью читает архив с проверкой ZIP CRC,
проверяет ARM soft-float ELF, BMP и все пути назначения. Допустим только известный
состав release ZIP: приложение, его иконки, два учебных примера и сопровождающие
тексты/лицензии. Второй `.app`, произвольный SGF или конфигурационный файл из ZIP
отвергаются. Дубликаты, регистровые коллизии, выход за корень и symlink в архиве,
пути книги или резервной копии запрещены.

Существующие SGF не заменяются, включая оба учебных примера. `sgf/`, каталог
партий, позиции, настройки и `system/config/extensions.cfg` установщик не меняет.
Для ассоциации SGF остаётся действие в меню самого приложения.

Перед заменой сохраняются точные исходные байты каждого заменяемого файла,
включая `view.json`, в отдельной сессии `local/reader-backups/<UTC-время>-<id>/`.
В `manifest.json` перечислены пути, действия, хеши до/после и `backup_path`.
Исходники лежат в `files/` с той же структурой каталогов. Сессия никогда не
заменяет предыдущую резервную копию.

Записи сначала подготавливаются во временных файлах в целевом каталоге,
сбрасываются через file `fsync`, перечитываются и заменяются атомарным rename.
Directory `fsync` применяется там, где файловая система его поддерживает.
После замены содержимое проверяется ещё раз. Unix `chmod`/`fchmod` не вызываются:
отсутствие таких прав на FAT не означает запрета записи файла. Установка
останавливается, если назначения изменились после построения плана.

При обнаруженном сбое записи или замены скрипт восстанавливает уже заменённые
файлы и убирает созданные файлы, после чего пишет статус `rolled-back` либо
`rollback-incomplete` в манифест. Пустые созданные каталоги могут остаться.
Неудача резервного копирования не затрагивает файлы книги. Потеря питания или
отключение USB не позволяют обеспечить транзакцию сразу для всех файлов;
резервная копия остаётся на компьютере. Если потребуется ручной откат, используй
точечные копии из `files/`, предварительно проверь хеши и изменения, сделанные
после установки. Восстановление всего старого `view.json` отменит и позднейшие
изменения других приложений.

SHA-256 и ZIP CRC обнаруживают ошибки передачи и записи, но не подтверждают
авторство архива. Для установки используй ZIP, собранный из проверенного исходного
кода.

## Воспроизведение иконок и локальные проверки

Оба изображения строятся из оригинального `assets/logos/logo-05.svg` («Книга»),
который создаётся общим C++ renderer. Обычный вариант — чёрный знак на белом,
focused — белый знак на чёрной скруглённой плитке. Размер 106×112; формат —
неупакованный 8-bit BMP с чёрными и белыми пикселями. Однобитный BMP намеренно
не используется из-за совместимости со старым `LoadBitmap`.

```bash
# Только для регенерации на компьютере нужен Pillow.
python3 scripts/generate-app-icons.py

# Синтетические каталоги и ZIP; реальная книга не нужна, Pillow не нужен.
python3 tests/installer_test.py
```

Тесты проверяют сохранение конфигурации и данных, идемпотентность, хеши резервных
копий, опасные архивы и назначения, конкурентное изменение до установки,
отказ file `fsync` и откат при ошибке replace. Они также моделируют запрет Unix
mode changes на FAT. Это host-проверки; поведение прошивки, E Ink и реального
USB/FAT они не подтверждают.

В0.3.1 размер уменьшен с192×192 до96×96 после проверки на Era: большой canvas
сдвигал подпись относительно соседних приложений. Ориентир по формату и размерам —
[практическая инструкция автора](https://github.com/jjrrw174/PocketBook-Desktop-and-App-Customizations/blob/main/README.md).

В0.6.0 поле значка изменено на106×112 для корректировки высоты подписи;
пропорции изображения книги сохраняются. Строка8-bit BMP имеет stride108.
Точное совпадение с baseline штатных значков проверяется на устройстве.
